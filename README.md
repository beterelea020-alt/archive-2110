# الأرشيف 21:10 — منصة تحقيق تفاعلية كاملة

واجهة عربية RTL + Backend APIs + PostgreSQL + إدارة الفصول والتوقيت + حسابات فرق + حفظ الإجابات + التلميحات + التصحيح ولوحة ترتيب الفرق.

## التقنيات

- **TypeScript** للواجهة والخادم.
- **Next.js App Router** لصفحات الموقع وواجهات API في تطبيق واحد.
- React 19 للواجهة، مع CSS مخصص وتصميم عربي متجاوب.
- PostgreSQL مع استعلامات مُعلّمة (parameterized queries).
- Cookies محمية بـ `HttpOnly` و`SameSite=Lax`، وجلسات JWT عبر `jose`، وتجزئة كلمات المرور بـ `bcryptjs`.
- توقيت الجدولة محسوب في قاعدة البيانات باستخدام المنطقة الزمنية `Africa/Cairo`.

## تشغيل محلي على Windows

المتطلبات: Node.js 22 أو إصدار LTS مدعوم، وDocker Desktop لتشغيل PostgreSQL محليًا.

1. فك ضغط المشروع وافتح PowerShell داخل المجلد.
2. انسخ ملف البيئة:

   ```powershell
   Copy-Item .env.example .env
   ```

3. افتح `.env` وعدّل القيم التالية:
   - `AUTH_SECRET`: سلسلة عشوائية طويلة لا تقل عن 32 حرفًا.
   - `ADMIN_EMAIL`: البريد الذي سيستخدمه مدير اللعبة.
   - `ADMIN_PASSWORD`: كلمة مرور قوية بطول 12 حرفًا على الأقل.
   - `GAME_DATE`: تاريخ يوم اللعبة بصيغة `YYYY-MM-DD`.
   - اترك `DATABASE_URL` كما هو للتشغيل عبر Docker المحلي، واجعل `DATABASE_SSL=false`.

4. شغّل قاعدة البيانات:

   ```powershell
   docker compose up -d
   ```

5. ثبّت الحزم وجهّز الجداول والفصول وحساب المدير:

   ```powershell
   npm install
   npm run db:setup
   ```

6. شغّل الموقع:

   ```powershell
   npm run dev
   ```

7. افتح `http://localhost:3000`. سجّل دخول المدير من بيانات `ADMIN_EMAIL` و`ADMIN_PASSWORD`، واللاعبون ينشئون حساباتهم من صفحة التسجيل.

## تشغيل قاعدة بيانات مستضافة والنشر

لربط Supabase وVercel خطوة بخطوة، راجع `README_SUPABASE_VERCEL.md`. تم ضبط أوامر إعداد/إعادة ضبط قاعدة البيانات لتقرأ `.env` صراحةً على Node.js 22.

يمكن استخدام PostgreSQL مستضاف من مزوّد مثل Neon أو Railway. أنشئ قاعدة البيانات أولًا، ثم ضع رابطها في `DATABASE_URL`. إذا طلب المزوّد TLS فاضبط `DATABASE_SSL=true` أو استخدم إعداد SSL الذي يوصي به المزوّد.

**خطوة مهمة قبل النشر:** نفّذ `npm run db:setup` مرة واحدة من جهازك مع توجيه `DATABASE_URL` إلى قاعدة البيانات المستضافة. يحتوي مجلد `private/` المحلي على تلميحات الإدارة وملف الحل السري، وهو مستبعد من Git عمدًا. لا ترفع ذلك المجلد إلى GitHub، خصوصًا إذا كان المستودع عامًا.

بعد إنشاء الجداول والحساب والفصول في قاعدة البيانات، ارفع مجلد المشروع إلى GitHub وانشره على Vercel أو استضفه على Node.js. أضف إلى Environment Variables في منصة الاستضافة قيم `DATABASE_URL` و`DATABASE_SSL` و`AUTH_SECRET`، ثم أعد النشر. يجب أن يستخدم الخادم وقاعدة البيانات نفس قاعدة البيانات التي جهزتها في الخطوة السابقة.

### رفع دليل الإدارة السري بأمان

بما أن الحل الكامل يجب ألا يصل للاعبين أو إلى مستودع عام:

1. احتفظ بملف `private/دليل_الإدارة_السري_للرفع.md` على جهاز المدير فقط.
2. سجّل دخول المدير إلى الموقع، ثم افتح **غرفة التحكم → الدليل السري**.
3. اختر ملف Markdown المرفق وارفعه. يُحفظ داخل جدول خاص بقاعدة البيانات، ولا يسترجعه إلا حساب يحمل دور `ADMIN`.
4. لا ترسل ملف الحل ولا حساب المدير إلى الفرق.

عند النشر من GitHub، مجلد `private/` مستبعد عبر `.gitignore`. ستظل تلميحات اللعبة نفسها محفوظة في قاعدة البيانات التي جرى تجهيزها محليًا، ولا يحتاج تشغيل الموقع المنشور إلى وجود ملف الحل ضمن ملفات الواجهة.

## صفحات الموقع

- `/` — صفحة تعريفية باللعبة.
- `/register` — إنشاء حساب لاعب وإنشاء فريق أو الانضمام بكود فريق.
- `/login` — تسجيل الدخول.
- `/dashboard` — لوحة اللاعب والفصول المفتوحة ومعلومات الفريق.
- `/chapters/1` إلى `/chapters/10` — الأدلة، حفظ الإجابات، وطلب التلميحات.
- `/leaderboard` — النقاط التي اعتمدتها الإدارة فقط.
- `/admin` — تعديل التاريخ والمواعيد، تصحيح الإجابات ونشر النتائج، ورفع دليل الحل السري.

## قواعد احتساب النقاط المطبقة

- صحة الإجابة: حتى 100 نقطة.
- الاستدلال: حتى 50 نقطة.
- مكافأة سرعة اختيارية: يمكن للإدارة تفعيل +5 نقاط إذا تم حفظ آخر إجابة خلال أول 15 دقيقة؛ وهي معطلة افتراضيًا حفاظًا على العدالة.
- كل تلميح مستخدم: خصم 10 نقاط.
- النتيجة المنشورة لا تظهر في ترتيب الفرق قبل اعتمادها من الإدارة.
- آخر إجابة محفوظة قبل الإغلاق هي الإجابة التي تصحح.
- كسر التعادل: مجموع نقاط الاستدلال، ثم نتيجة الدور العاشر، ثم عدد الأدوار ذات 100 نقطة أساسية؛ لا يُستخدم توقيت الإنترنت لكسر التعادل، ويظل التعادل المشترك ظاهرًا إذا استمرت المساواة.

## ملاحظات أمان وتشغيل

- لا يوجد حساب مدير افتراضي مضمن داخل الكود؛ ينشئ `db:setup` حساب الإدارة فقط عند ضبط `ADMIN_EMAIL` و`ADMIN_PASSWORD`.
- الواجهة لا ترسل محتوى فصل غير مفتوح من API، ولا تُرجع التلميحات قبل موعد فتح الدور.
- endpoints الإدارة تتحقق من دور المستخدم على الخادم؛ إخفاء عناصر الواجهة وحده ليس وسيلة الحماية.
- استخدم HTTPS في النشر، وقاعدة بيانات مُدارة مع نسخ احتياطي. حدّث Next.js والحزم إلى أحدث إصدار أمني متوافق قبل إطلاق عام، ونفّذ اختبارًا على بيئة staging.
- هذا مشروع بداية عملي ومتكامل الوظائف الأساسية، لكنه لم يُنشر فعليًا إلى نطاق عام ولم يُختبر على قاعدة بيانات مستضافة ضمن هذه البيئة. يلزم إعداد متغيرات البيئة وتشغيل الاختبارات قبل استقبال المستخدمين الحقيقيين.

## أوامر مساعدة

```powershell
npm run typecheck
npm run build
npm run start
```

`npm run db:reset` يحذف جميع جداول اللعبة، ولا يعمل إلا إذا شُغّل صراحةً مع متغير `CONFIRM_DB_RESET=YES`. استخدمه فقط على قاعدة اختبارية؛ لا تستخدمه على بيانات اللعبة الحقيقية.
